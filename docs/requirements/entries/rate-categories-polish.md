# Rate Categories polish: legacy layout, season cards, SKU per season, compact rates

Owner feedback 2026-10-25 (no ticket). Branch `fix/rate-categories-legacy-layout`. Builds on [184-rate-categories.md](184-rate-categories.md).
Legacy was read only (`RateCategoriesEdit.vue`, `RateCategoriesLookups.vue`, `Shared/RateCategoryTable.vue`, `SideBarControl.vue`) and described in our own words; nothing was copied.
**Status:** in review, 2026-10-25. Not verified in a real browser by a person: layout was checked in headless Chrome screenshots of a demo build (1400px) and in jsdom tests.

## What legacy does

- **Left list (`SideBarControl`):** one column. "New Rate Category" is the FIRST row of the same list (a green outlined box), not a separate control; clicking it adds a "New Rate Category" row in the list and selects it. Each row: padding 15px top and bottom, 10px left, 10px margin above, 4px radius, `margin-right: 15px`; hover is a light green; the active row is green with white text and a 5px green bar on the right edge; inactive categories are faded.
- **Item / Combo:** two radios (Item, Combo) above one "SKU Lookup", on the category. Choosing Item shows the item lookup, Combo the combo lookup. Missing from the build? It was rendered (right aligned, no label); it read as a stray control. Now it has the visible label "SKU Type" and sits left, directly above the lookup.
- **Add Season:** a filled primary (green) button under the table, disabled while a new season is unsaved or there are no room types.
- **SKU:** `itemID` / `itemComboID` exist on the **rate category only**. The season (`Rate`) model has `name`, `startDate`, `endDate`, `isDefault` and the room type rows; there is no SKU on a season, and the default season has none either.
- **Season look:** the table is one grid; the default season is grey, the others are separated by a thick (3px) rule; the lilac, sky blue and peach fills tint groups of weekday and guest columns, not seasons. Season cell: name, start "to" end dates, then underlined text links "duplicate season" and "remove season". Table text 14px, cell padding 5px (header 8px), rows 50px high, columns at least 80px (160px for the season column); the focused cell is highlighted.

## Season SKU on the wire (review)

The default season carries neither `sku` nor `skuKind`; a dated season carries `skuKind` only with a `sku` (the form keeps a kind without a SKU to show the radio, and `normalizeRateCategory` drops it on save). The mock answers 422 and the http guard refuses otherwise (`isSeasonSkuShapeValid`). Messages read "Select an item SKU." and "Select a combo SKU.".

## Manual check list (real browser)

1. At 1400px, Member Rate: the table shows no horizontal scroll (13 columns); at 1200px it scrolls inside its box, the room type column stays, the season title rows stay in view, the page itself does not scroll sideways.
2. Type 12,500.00 and 1,250.00 in an amount field: the whole value is visible.
3. Add Season: focus lands in the new season's name; Tab reaches the dates, SKU type, SKU lookup, duplicate and remove.
4. Leave a season unnamed and Save: the red message sits on a white chip, readable on every season colour.
5. The list: "New Rate Category" is one row; clicking it turns it into the selected row; clicking it again does nothing; inactive categories show the red Inactive tag.
6. Add seven seasons: the colours repeat after six, the names and dates stay readable.
