## Placeholders and invented values

- **P-21-1:** the three seeded unassigned reservations (`UNASSIGNED_SEEDS` in `src/api/scheduleData.ts`, confirmation numbers GR-50411 to GR-50413; first written as GR-50401 to GR-50403, which the Reservation List mock already uses) appear on the grid only. `isSeededUnassigned` keeps them out of the Reservation List mock, which has its own list-only unassigned reservations (`EXTRA_SEEDS`).
- **P-21-2:** `RoomHousekeepingStatus` (`'clean' | 'dirty'`, the room-level placeholder from ticket 2.3) was renamed from `HousekeepingStatus` so it does not collide with the block-level `HousekeepingStatus` of the "H" chip.
- **P-21-3:** the mock block GR-50351 (Marcus Feldman, Room 101) is a linked-room block pointing at Room 102, "Beatrice Quinn", so the linked block can be seen. The real link data comes from the backend (`ScheduleBlock.linkedTo`: room number and reserver name).
- **Not built, by decision:** no "canceled" block state. The owner answered Q-21-3 (2026-10-24): canceling removes the event from the schedule, as in the legacy system, so the ticket's canceled-state acceptance criterion is dropped. Treatment icons and name colors are ticket 3.11.
- **Housekeeping chip sizes (not tokenized):** the chip's 10px letter, 8px "+", 0.625-spacing radius and 2px focus outline stay literal in `HousekeepingChip.tsx`. `src/theme.ts` has no size or chip token pattern; its 2px focus outlines are literals inside component overrides, and the chip is a plain button outside them.
